# Wisp handoff

For the next Claude session working on Wisp. Read this first.

Wisp is open-source firmware for the Spotify Car Thing, plus its Android app
("the Wisp app", also called Wisp Companion).
Repo: github.com/picovrfbt/WispOS. Website: picovrfbt.github.io/WispOS,
served from `docs/`.

## The owner

- Not a programmer. Explain in plain words and keep answers short.
  Screenshots and pictures help.
- File cards and attachments display badly for them. Put text inline (code
  blocks for anything they paste) and link pictures on GitHub.
- They're often low on usage credit, so work efficiently.

## Rules (keep in force)

- **Release only when asked** ("release it", "push it all"). Never tag,
  publish or change a GitHub release on your own.
- **Commit and push only when asked.** Commit as
  `picovrfbt <90056887+picovrfbt@users.noreply.github.com>`, never the
  personal email.
- **Never handle secrets**: no GitHub tokens, no Android signing keystore
  (`WISP_KEYSTORE_B64`), no OAuth client secrets or passwords. Never commit
  `dev-device/config/state.json` (the owner's Spotify login).
- **Don't touch the owner's real phone or Car Thing** unless they set it up
  and ask. Test with the fakes in the test files.
- Keep the Car Thing light on memory.
- Don't re-propose Android Auto/CarPlay, an iPhone app, OBD-II or a mic
  visualizer.
- Ask before downloading anything big. **Show options before redesigning a
  screen.**
- Keep each file's existing line endings.
- On longer jobs, say what you're doing as you go.

## Where things are

- `wisp-daemon/daemon`: the Car Thing's Go service (librespot-based). Its API
  is on 127.0.0.1:3678, with a websocket at `/events`.
  Test: `go test ./daemon/...` from `wisp-daemon`.
- `wisp-ui`: the Car Thing's screen (React/Vite, a fixed 800x480 screen).
  - Test: `npx tsc -b && npx vitest run`.
  - Format only the files you changed: `npx prettier --write <files>`.
    Running it on all of `src` reformats unrelated files.
  - To force a screen during development, set localStorage
    `wisp.dev.forcedScreen` (the list is in `src/dev/DevScreens.tsx`).
- `wisp-companion/app`: the Wisp app (Kotlin, package `dev.carthingfw.nav`).
  - Build and test:
    `./gradlew :app:compileDebugKotlin :app:testDebugUnitTest`.
  - `NavServer` is the websocket server the Car Thing connects to.
- `relay/`: the Cloudflare relay that carries passenger-mode messages.
  `docs/relay.json` lists the relays in use.
- `docs/`: the website.
  - `docs/new/X.Y.Z.html` holds one What's new page per release.
  - `docs/updates.html` is generated by `tools/updates_page.py` from
    CHANGELOG.md. Edit the template in the script, not the page.
- `QUEUE.md`: things the owner asked for but hasn't said to start.
- Debug screen on the Car Thing: hold buttons 1 and 4.

## How to release

1. In CHANGELOG.md, turn "Unreleased" into `## vX.Y.Z (date)` with a
   one-line intro.
2. Write `docs/new/X.Y.Z.html` from the previous page's frame.
3. Point the `class="ver"` badge on every page in `docs/` and `docs/new/`,
   and the `hero-pill` in `docs/index.html`, at the new page.
4. Run `python tools/updates_page.py`.
5. If the app changed, bump `versionCode`/`versionName` in
   `wisp-companion/app/build.gradle.kts`.
6. Commit and push main, then create the tag: push it, or run
   `.github/workflows/release.yml` by hand with input `tag: vX.Y.Z`, which
   creates the tag and the release. (Cloud sessions couldn't push tags.)
7. Give the owner the release notes as text in a code block, and ask them to
   set the release title to "Wisp X.Y.Z" (no "v").

  The owner was asked to set the title to "Wisp 1.0.7" and paste the notes;
  check that's done.

- What 1.0.7 brought:
  - Address search: a knob keyboard on Where to? → Search; voice "take me
    to…" with a list of matches to pick from; and "Find a place on the Car
    Thing" in the Wisp app.

  when the owner says.
